# PRD: несколько чатов на одном экране (split view)

Эпик канбана: `t_d7e7f0d6`. Изменения аддитивные: пока панель одна, приложение ведёт себя как раньше.

## Цель

Дать возможность держать на одном экране 2–4 живых чата (телефон и десктоп): читать ответы в двух местах,
сравнивать ботов, не переключаясь по сайдбару. Раскладка — дерево бинарных разбиений, а не сетка: сетка не умеет
«слева 60 % в две строки, справа один чат».

## Пользователь и сценарии

1. **Разделить экран.** Кнопка в шапке справа (иконка `Lucide.PanelsTopLeft`, на десктопе `Ctrl+\`) или
   перетаскивание чата из сайдбара. Текущий чат сжимается до половины, вторая половина — «Choose a chat».
2. **Выбрать чат.** Тап по строке в пустой панели открывает этот чат в ней и переводит фокус.
3. **Три и четыре панели.** Повторное нажатие делит панель под фокусом: 2 → 3 → 4, дальше кнопка неактивна.
4. **Регулировка.** Границу тянут пальцем/мышью; двойной тап по границе возвращает 50/50; панель не сжимается
   меньше минимума.
5. **Закрыть.** Крестик на панели убирает её, дерево схлопывается, соседи занимают место.
6. **Фокус.** Ввод, микрофон, чтение вслух, `Ctrl+F`, хоткеи — только в панели под фокусом, она обведена.
7. **Живучесть.** Оба чата стримят одновременно, поворот экрана и смерть процесса раскладку сохраняют.
8. **Десктоп.** Плюс drag-and-drop из сайдбара: в центр панели — заменить чат, к краю — разделить в эту сторону.

## Что меняем

- `shared/ui/.../ui/split/` — новое: `SplitLayout.kt` (модель + `Saver`), `SplitContainer.kt` (границы),
  `PaneChatHost.kt` (свой `ChatHost`/`ChatViewModel` на панель), `SplitScreen.kt` (экран), `SplitDragAndDrop.kt`.
- `shared/ui/.../ui/App.kt` — ветка `else -> ProvideReplySpeaker(speaker) { ChatScreen(...) }` заменяется на
  `SplitScreen` с `rememberSaveable(saver = SplitLayout.Saver)`; `openSession`/deep link открывают чат в панели
  под фокусом (`replace(focused, …)`), а не сбрасывают раскладку.
- `shared/ui/.../ui/Shortcuts.kt` — новый `Shortcut.SplitScreen` (`Ctrl+\`).
- `shared/ui/.../ui/sessions/SessionsSidebar.kt` — источник перетаскивания + пункт меню «Open beside» на телефоне.

## Что НЕ трогаем

- Одиночный чат: шапка, композер, вложения, диктовка, чтение вслух, комментарии, баннеры «другой чат» — поведение
  и разметка остаются прежними при одной панели.
- Отдельное окно чата на десктопе (`ChatWindow.kt`) — только образец, не переписывается.
- Wear: без drag-and-drop.
- Раскладка не пишется в настройки: живёт до перезапуска процесса (поворот/смерть процесса — через `Saver`).
- Больше 4 панелей.

## Критерии приёмки

Совпадают с приёмкой эпика (8 пунктов) и проверяются: юнит- и Compose-тестами (`:shared:ui:jvmTest`), ревью
по диффу `App.kt`, и живым прогоном на телефоне (SM-S938B, `assembleRelease` + `adb install`) — см. карточку
E2E. Ключевые проверяемые утверждения:

| # | Утверждение | Чем доказано |
|---|---|---|
| 1 | Split даёт 2 панели: сверху текущий, снизу «Choose a chat»; выбор ставит чат вниз | `SplitScreenTest`, прогон на телефоне |
| 2 | 2-е нажатие → 3 панели, 3-е → 2×2, 4-е — кнопка неактивна | `SplitLayoutTest`, `SplitScreenTest` |
| 3 | Граница тянется, минимум соблюдён, двойной тап = 50/50 | `SplitContainerTest`, `resize` в `SplitLayoutTest` |
| 4 | Крестик закрывает панель, дерево схлопывается без веток с одним ребёнком | `SplitLayoutTest.close`, `SplitScreenTest` |
| 5 | Ввод/микрофон/озвучка/клавиши только в панели под фокусом, она обведена | `SplitScreenTest` (фокус), ревью |
| 6 | Оба чата стримят, поворот сохраняет раскладку и чаты | `SplitLayout.Saver` round-trip, прогон на телефоне |
| 7 | Десктоп: drag из сайдбара (центр/край), `Ctrl+\` | `SplitDropZoneTest`, ревью |
| 8 | Нет ложных «другой чат ответил» по открытым панелям | `holdSideChat`/`releaseSideChat`, лог на телефоне |

## Нефункциональные требования

- Перетаскивание границы не пересоздаёт `ChatViewModel` и не вызывает взаимных рекомпозиций панелей
  (`key(pane.id)`, никакого `animateContentSize`); никаких задержек/накопления состояния в драге.
- Минимальный размер панели: телефон 240×200 dp, десктоп 320×240 dp; доля ветки всегда `0.15f..0.85f`.
- Существующие тесты `:shared:ui:jvmTest` и `:shared:core:jvmTest` остаются зелёными.

## Риски

1. **Регрессия одиночного чата** — самая вероятная: правка `App.kt` трогает корневую ветку. Смягчение: пункт 1
   карточки `t_b07ca085` и тест регрессии в `t_3db5f51b`.
2. **Ложные уведомления** «другой чат ответил»: если панель не вызвала `holdSideChat`, watcher сыпет баннерами.
3. **Производительность на телефоне** при двух стримах + драге: держать панели независимыми поддеревьями
   композиции; проверять руками, а не «на глаз по коду».
4. **Гонка двух панелей с одной сессией** (один и тот же чат в двух панелях): `ChatHost` на панель, состояние
   не делится; при сомнении — запретить повторный чат в двух панелях через `replace`-проверку.
5. **Сохранение раскладки** — битая строка `Saver` не должна ронять приложение (возврат `null`).
